# 导航所有权与缓存复用

在排查点击延迟、整块白屏或随机回访仍加载时阅读。

## 先找切换等待了什么

沿实际调用链记录事件处理、状态更新、路由/RSC 请求、API、缓存读取和渲染提交。常见不同原因：

| 证据 | 候选改动 | 必须保留的边界 |
| --- | --- | --- |
| 客户端列表切换也等待服务端路由往返 | 显式声明客户端视图导航 | 服务端拥有的参数仍执行服务端逻辑 |
| 首次跨页面只有 loading shell 被预取 | 核对框架版本的预取策略，必要时对高意图入口完整预取 | 不对所有动态页面无条件预取 |
| 相同版本回访反复取数 | 稳定 query key、合理保留与请求合并 | 权限和内容版本失效仍生效 |
| 已有数据在 refetch 时被清空 | 同身份内容保留，局部更新 loading/error | 不展示另一个条目的旧结果 |
| 网络很快但提交慢 | 分析重渲染、长任务和大列表 | 基于采样再决定拆分或虚拟化 |

## URL 与点击契约

先写所有权表：路由、客户端参数、服务端参数、权限/工作区边界、锚点、是否允许本地切换。一个页面可同时存在客户端和服务端参数。

只拦截显式允许的客户端状态变化：

- 使用当前框架已支持的 History 或 shallow navigation 集成；确认 URL 订阅和 Back/Forward 会更新 UI。React transition 只调整调度，不能省去本来必需的网络请求。
- 解析实际渲染的 href，保留框架注入的 base path、完整 query 和 anchor。验证同源、允许的路径及参数差异；额外未知参数变化回退框架导航。
- 仅处理未取消的普通主键点击；保留 Ctrl/Cmd/Shift/Alt、中键、download 和非当前窗口 target 的浏览器行为。
- 让调用方已有的取消回调、replace、滚动和导航保护生效；相同目标避免重复历史项。
- 使用真实 anchor/框架 Link，避免普通按钮加全局 preventDefault。移动菜单的关闭回调只关闭菜单，不再触发第二次导航。

Next App Router 的同路径 query 可能触发 RSC。只有调用链证实参数全由客户端消费时才使用本地 History；不要全局替换 router.push。动态路由的自动预取可能止于 loading boundary，需按当前版本与网络记录验证。纯客户端视图变化不需要无用的 RSC 预取；新标签工具链接通常也不需要投机预取。

## 缓存与调度

- 将“路由代码/服务端载荷预取”与“业务数据缓存”分开观察，两者命中并不等价。
- 保持 QueryClient/缓存容器在布局层稳定存在，避免换页重建；排查 stale 与 gc/retention 的不同作用，以及 refetchOnMount/focus 行为。
- 结果身份纳入权限范围、原文/上下文版本、语言及实际影响结果的配置。持久缓存恢复前取得当前授权与版本，登出清理账号数据；多人可共享同权限同版本结果，不共享私人结果。
- 未改内容复用已完成结果；变更只使受影响的依赖失效。旧响应只能写入自己的版本，不能覆盖当前条目；不要用另一条目或语言作 placeholder。
- 当前内容优先，hover/focus 表达意图时预取，再按收益准备邻近内容。队列的并发、总量、字节和保留时间可配置；离开页面停止投机调度，不能取消其他活跃读者共用的计算。
- 同身份请求合并；进程外合并若使用租约，需要所有者校验和过期写入防护。只有测量显示跨进程重复计算时才引入这一层复杂度。
- 对需要实时性的内容定义通知和失效契约；通知只更新受影响条目，重连做版本对账。TTL 是保留/兜底策略，不是正确性证明。

按浏览器热、服务端热、完全冷、磁盘恢复和版本变化分别验收。发现慢在 API/SQL/依赖时提供阶段证据，再修改对应环节；不要先改模型掩盖触发或渲染问题。
