# 可归因的浏览器验收

在建立基线、验证实现和发布后复验时阅读。按改动选择证据，不把所有观测工具强行用一遍。

## 测量契约

先定义起止点和工具：

| 指标 | 起止点 | 不等同于 |
| --- | --- | --- |
| 点击反馈 | 输入事件至菜单/外壳首次反馈 | 数据可用 |
| 首个可读内容 | 输入事件至当前目标的可读内容绘制 | AI 全部完成 |
| 数据完成 | 请求开始至目标版本数据可用 | 页面绘制 |
| 动效完成 | 动效开始至自然结束 | 网络延迟 |
| API/依赖耗时 | 同 trace 的服务端 span | 浏览器端完整时延 |

浏览器性能记录、Event Timing/应用标记、网络 timing 和服务端 tracing 各回答不同问题。使用同一 navigation/trace 标识关联；跨进程时钟不同，不能直接相减当网络耗时，不能把重叠 span 简单相加。没有页面内计时能力时，把工具调用到观察的耗时标注为含自动化开销的上界，不冒充 INP。

固定对照条件：提交/构建、浏览器和前后台状态、路由与数据、视口、网络/CPU 设置、缓存状态、预取命中。区分首次访问和重复切换，保留样本数及原始数据；样本不足只报告样本分布，不宣称生产 P95/P99。Lighthouse 初载得分不能证明应用内切换顺滑。

只有长任务或提交耗时集中时再做 CPU/React profiling；只有服务端耗时占主导时再追 SQL、队列或模型。对照改动尽量隔离导航、缓存与动效，分别说明“更快”和“感觉更连贯”的证据。

## 回归矩阵

| 场景 | 要确认的契约 |
| --- | --- |
| 客户端视图切换 | URL、active 和内容一致；没有不必要的服务端路由请求 |
| 服务端参数/其他路径 | 服务端逻辑确实执行，没有被浅路由绕过 |
| base path、工作区、锚点、未知 query | 正确保留或回退，不能串到另一范围 |
| Back/Forward、replace、取消 | 历史、守卫与视图一致 |
| Cmd/Ctrl、中键、新标签、刷新深链接 | 保留浏览器行为，目标独立可恢复 |
| 快速点击与旧请求晚到 | 最后目标获胜，旧数据不覆盖当前版本 |
| 未保存输入、焦点、滚动 | 无非预期 remount 或丢失；按产品契约处理离开页面 |
| 冷、热、恢复、版本更新 | 路径分别测量，权限变化不能恢复旧身份数据 |
| 折叠、resize、长标签 | 指示背景与目标 rect 最终一致 |
| loading、empty、error、后台回填 | 明确可用状态，后台更新不造成整块闪白 |
| reduced motion | 初始偏好及运行中改变均有覆盖；说明实测或仅代码检查 |

测试分层：纯逻辑测试验证目标判断；真实框架夹具验证 RSC/历史/base path；浏览器验证几何、中间帧与输入保留。夹具使用合成数据并复用生产组件。不要为使 source-string 测试变绿而删除滚动/状态契约；组件替换后把断言更新到相同语义，并补足浏览器证据。

## 发布与报告

- 用户只要求方案或分析时不发布。已有实施/发布授权时完成必要检查，追踪最终 SHA 的 CI 与实际部署作业；合并成功和旧流水线通过都不代表新版本已上线。
- 检查部署健康后用自己的标签页加载新构建，验证可用页面与关键切换。线上验收用只读操作；写操作使用明确允许的测试环境与测试记录，不保存真实配置来证明导航可用。
- 运行项目要求的类型、格式和相关测试。失败时区分实现回归、过时断言和环境问题，不能跳过阻止合并的检查。
- 控制台日志按发布后时间窗口筛选；部署重启前的连接错误不能被算成新构建的运行错误，也不能隐瞒持续存在的问题。
- 保存结果：版本、环境、路径、样本条件、起止点、改前/改后、实际行为、证据与限制。截图配合测量数据，不虚构百分比或 FPS。
- 交付后恢复临时视口/限速设置，停止自建服务，清理自己的临时标签；只保留用户需要的结果页，不关闭用户原有标签。
