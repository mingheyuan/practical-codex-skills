# 前端导航流畅度

改善已有应用的切换响应与运动连续性。先判断用户要的是“点击后更快可用”“消除整块白屏”还是“参考站的滑动和入场节奏”；按实际诉求选择工作，不把动效当成性能优化的证明。

## 建立证据与边界

- 阅读仓库约定、路由和数据加载实现。追踪点击 → URL/状态更新 → 路由请求 → 数据读取 → React 提交 → 可见内容，确认真正阻塞切换的环节。
- 若有参考站，在已授权的页面实际切换，记录 DOM、计算样式、动画方向、时长、缓动、加载边界及折叠行为。截图不能证明中间帧；无法登录或测量时明确限制，不猜实现。
- 区分路由外壳出现、首个可读内容、数据加载完成与后台 AI 完成。按需读取网络瀑布、浏览器性能记录、React Profiler 或服务端 trace；只有证据指向后端或模型时再扩展范围。
- 先记录同浏览器、同数据和同缓存状态的基线。冷启动、预取命中、重复访问、持久缓存恢复、前台与后台标签分别记录。

## 根据瓶颈实施

### 导航与数据

阅读 [references/navigation-and-cache.md](references/navigation-and-cache.md)。

- 逐条声明 URL 参数由客户端还是服务端拥有；只有确认客户端拥有的视图变化，才考虑框架支持的 History/浅路由路径。路径相同不代表参数都归客户端。
- 恢复真实链接语义和路由预取，保留取消导航、历史记录、深链接、修饰键与部署 base path。跨路由仍使用框架路由。
- 用稳定的页面外壳和精确版本缓存消除重复白屏。先处理当前可见内容，再做受预算约束的意图预取；不靠无限缓存、无限并发或无条件全量预取制造快的假象。

### 侧栏与内容动效

阅读 [references/navigation-motion.md](references/navigation-motion.md)。

- 侧栏用一个可测量的装饰背景在真实目标间移动；位置来自布局，不写死菜单索引和坐标。
- 在稳定挂载的内容节点上做短暂入场；不等待退场完成才导航，不靠更换 React key 重挂载业务子树。
- 动效身份只包含改变页面呈现的路由/视图状态；数据补全、翻译回填、搜索和分页是否重播，由产品语义决定。
- 时长、位移和缓动使用可覆盖的样式 token。参考值是特定产品的选择，不是通用验收阈值；遵循 reduced motion。

## 验收与交付

阅读 [references/acceptance.md](references/acceptance.md)，按改动范围选择测试。

1. 纯逻辑测试覆盖目标解析与回退；路由行为用真实框架夹具验证；视觉几何和中间帧用浏览器验证。mock 路由只用于隔离动效，不能证明真实路由正确。
2. 对照验证 URL、内容、选中项、历史和未保存状态。检查快速连点、折叠/展开、后台刷新以及旧请求晚到。
3. 在用户授权的目标环境跟踪最终提交的 CI、合并和部署；部署健康后再刷新自己的验收页。已有授权继续有效，但 skill 本身不授权发布或修改真实业务记录。
4. 报告具体变化、测试结果、样本条件和未验证范围。性能数字附测量口径；保留实际截图及必要的中间帧数据。恢复临时视口，关闭自建测试服务和临时标签。

## 实施约束

- 从输入、权限和路由结构推导行为，不为某用户、记录 ID、业务词或测试样本写旁路。
- 延迟、并发、容量等运维参数通过项目配置管理；路由能力通过声明表达，不靠字符串猜测业务语义。
- 保留认证、授权、错误态与人工操作。缓存不能替代权限检查；失败不伪装成成功，不额外加入无依据的模型调用、输出截断或重试。
- 优先沿用现有组件、框架和主题。只有实际需求证明有收益时才新增依赖；不为模仿交互复制参考站品牌、内容或资产。
